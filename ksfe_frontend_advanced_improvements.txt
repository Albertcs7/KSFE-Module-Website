KSFE Insurance Module - Advanced Frontend Improvements

1. Server State Management & Caching (TanStack Vue Query)
   - Issue: Fetching data directly into Pinia stores or components can lead to complex state management, manual cache invalidation, and race conditions.
   - Improvement: Implement TanStack Vue Query for API calls. It provides out-of-the-box caching, background data syncing, automatic retries on failure, and optimistic UI updates. Pinia should then be strictly reserved for global UI state (like dark mode or sidebar toggles).

2. Architecture: Reusable Composables (Vue 3)
   - Issue: Components can become bloated if they handle both UI rendering and complex business logic (e.g., filtering, formatting, API calling).
   - Improvement: Extract business logic into specialized composable functions (e.g., `useSLIPolicies()`, `useUserPermissions()`). This keeps Vue components lightweight (focused on template/UI) and makes the logic highly testable and reusable.

3. Performance Optimizations
   - Virtual Scrolling: If the GIS or SLI dashboards display hundreds of rows (policies, transactions), implement virtual scrolling (e.g., using `vueuse/core` or `vue-virtual-scroller`). This renders only the rows visible on screen, dramatically improving DOM performance.
   - Lazy Loading Modals: Ensure heavy components like `GISRemittanceModal.vue` or `SLIEditUserModal.vue` are imported using `defineAsyncComponent`. This prevents them from loading until the user actually clicks to open them, reducing the initial JavaScript bundle size.

4. Robust Error Handling & Telemetry
   - Global Error Boundary: Implement a global `app.config.errorHandler` in your Vue instance to catch unhandled errors. Show a graceful "Something went wrong" UI instead of the app crashing or freezing.
   - Error Tracking: Prepare the frontend to integrate with an error tracking service (like Sentry) so that frontend crashes or unhandled promise rejections are logged automatically for the development team.

5. Advanced UI/UX & Accessibility (a11y)
   - Skeleton Screens: Replace standard loading spinners with skeleton loaders that mimic the shape of the data. This significantly improves the "perceived" loading speed for the user.
   - Keyboard Navigation: Ensure all interactive elements (modals, dropdowns, table rows) are fully navigable via the `Tab` key and have proper ARIA attributes. This is crucial for enterprise software compliance.

6. End-to-End Type Safety
   - OpenAPI Code Generation: If your backend team uses Swagger/OpenAPI, generate your TypeScript types and API client automatically (using tools like `openapi-typescript-codegen`). This ensures the frontend will throw compile errors immediately if the backend changes an API response structure.
   - Strict TypeScript: Ensure `strict: true` is enabled in `tsconfig.json`.

7. Automated Testing Strategy
   - Unit Tests: Use `Vitest` to write tests for your Pinia stores, router guards, and composables.
   - Component Tests: Use `Vue Test Utils` to mount your Vue components in isolation and verify they render correctly based on props.
