CRITICAL ISSUES
- Missing/incorrect production authentication & authorization:
  - The backend always returns a hard-coded permissions set (`forcedPermissions`) instead of using real permissions from the external auth response — see apps/backend/src/core/auth/auth.service.ts. This is a broken access-control foundation: users will have excessive permissions (or wrong ones) in production.
- No token revocation / refresh token persistence: refresh tokens are signed and issued in a cookie but no server-side storage or revocation check exists — see apps/backend/src/core/auth/auth.contoller.ts. Compromise of a refresh token cannot be revoked.
- Empty permission middleware: apps/backend/src/core/auth/permission.middleware.ts is empty — authorization enforcement is brittle and inconsistent.
- Incomplete CORS origin list / placeholder host: allowed origins include a placeholder value and origin logic is brittle — see apps/backend/src/app.ts. This can lead to accidental open CORS or blocking legitimate hosts.
- Sensitive data logging to console: external auth client logs full payloads and full Axios errors: apps/backend/src/integrations/external-auth/externalAuth.client.ts. This risks leaking credentials and PII in logs.

HIGH PRIORITY ISSUES
- Weak JWT verification hardening: `jwt.verify(token, JWT_SECRET)` is used without explicit algorithm, issuer, audience checks; no `kid` handling or rotation strategy — apps/backend/src/core/auth/auth.middleware.ts.
- Race conditions around remittance/cheque attachments: create-then-select-then-update pattern (createChequeAndAttachService → select remittances → attach) is vulnerable to concurrent runs producing inconsistent attachments or double-processing; no SELECT ... FOR UPDATE or optimistic locking — apps/backend/src/modules/insurance/insurance.service.ts and apps/backend/src/modules/insurance/insurance.repository.ts.
- Missing input sanitization / excel injection risk: fields like `employee_name`, `receipt_no` are accepted and logged with no sanitization — risk of CSV/Excel formula injection and XSS on exported reports.
- Error handling leakage & inconsistent status codes: controllers often return 400 for internal server errors; some errors rethrow raw `err.message` (leaks internals). Example: update/delete controllers return 400 on DB errors rather than 5xx.
- No rate limiting / brute force protection on auth endpoints: `/auth/login` is unprotected; no account lockout or IP throttling.
- DB pool small/untuned for production: connectionLimit: 10 hard-coded — no environment-driven tuning and no graceful handling for DB outages — apps/backend/src/database/mysql.ts.

- Unclear unique constraints usage documented vs code: code expects ER_DUP_ENTRY for remittance unique(employee_policy_id, salary_month) and receipt_no. Need explicit schema verification and migration scripts.

SECURITY RISKS
- JWT misuse: missing algorithm & claim validation, no explicit token audience/issuer, no refresh token storage or rotation → token replay risk.
- Privilege escalation via forcedPermissions: always granting broad permissions is a direct broken access control issue.
- Sensitive logging: external auth logs request bodies and full Axios errors (includes tokens/passwords).
- Missing CSRF protection for cookie-based refresh endpoint: refresh token cookie is set with SameSite=Lax (partial) but the `refreshController` relies only on the cookie and is reachable as POST — attacker can exploit certain flows. No CSRF token or strict SameSite=strict for sensitive operations.
- CORS misconfiguration risk: allowedOrigins contains a placeholder and is not configurable from env; Vary header missing — may leak cookies to wrong origins if mis-set.
- No rate limiting / brute force prevention on `/auth/login`.
- Possible SQL injection vectors in any function that builds queries by concatenation (some code builds placeholders inline) — though parameterized queries are used widely, double-check dynamic SQL building.
- Excel injection: strings written to exported Excel/CSV directly without prefix-sanitization (`'`, `+`, `-`, `=`) risk formula injection on Excel.
- File upload & parsing not found — if present later, must sanitize and scan for malware.
