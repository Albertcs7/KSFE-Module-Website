KSFE Project - Codebase Analysis & Recommendations
Date: 2026-05-18

Summary
-------
- Scope: full repo at apps/backend and apps/frontend (auth + insurance features).
- Goal: identify unnecessary/unused code, highlight risks, and propose actionable improvements.

High-level findings
-------------------
- The backend is functional and reasonably well organized into small modules (`auth`, `insurance`, `integrations`).
- The codebase contains production-grade pieces (PDF generation via Puppeteer, Excel export via ExcelJS, JWT refresh sessions, structured logging).
- Several maintenance and operational concerns surfaced that should be addressed to improve reliability, security, and developer ergonomics.

Unnecessary, redundant, or questionable code and dependencies
-----------------------------------------------------------
- Duplicate/workspace-level dependencies:
  - `puppeteer` appears both at the repository root and in `apps/backend/package.json`. Prefer a single location (backend only) to avoid installing heavy browser binaries in the workspace root.
    - Files: [package.json](package.json) and [apps/backend/package.json](apps/backend/package.json)

- Heavy runtime dependency with operational risk:
  - `puppeteer` (PDF generation) is valid, but it increases deployment complexity (binary downloads, memory usage). Consider replacing with `puppeteer-core` + a separate browser provider (or a dedicated service) or run inside an isolated container with resource limits.
    - File: [apps/backend/src/modules/insurance/insurance.service.ts](apps/backend/src/modules/insurance/insurance.service.ts)

- In-memory refresh session store:
  - `refreshSessions` is stored in-process (Map). This loses sessions on restarts and does not scale across instances. Use Redis or another persistent store for production.
    - File: [apps/backend/src/core/auth/auth.session.ts](apps/backend/src/core/auth/auth.session.ts)

- `.gitkeep` placeholders and empty folders:
  - Several directories contain `.gitkeep`. Keep them if they are intentionally empty; otherwise remove when unused. Examples: [apps/backend/src/core/errors/.gitkeep](apps/backend/src/core/errors/.gitkeep), [apps/backend/src/core/logger/.gitkeep](apps/backend/src/core/logger/.gitkeep)

- Root-level `winston` and `axios` entries:
  - `winston` and `axios` appear as top-level dependencies in the repo root (see [package.json](package.json)). If only backend uses these, move them into `apps/backend` to avoid installing server libs for frontend-only developers.

Dead or low-value code patterns to review
---------------------------------------
- Hardcoded or 'forced' permissions/modules in `loginService`:
  - The service includes `forcedPermissions` / `forcedModules` (temporary measure). This can mask real auth problems and complicate audits. Replace with a mapping strategy or remove after integration testing with the external auth provider.
    - File: [apps/backend/src/core/auth/auth.service.ts](apps/backend/src/core/auth/auth.service.ts)

- Large single-file services:
  - `insurance.service.ts` is long and mixes business logic, HTML template generation, PDF orchestration, and Excel export. Split into smaller units:
    - `report-renderer` (HTML + helper formatters), `pdf-generator` (puppeteer orchestration + queue), `excel-export` (ExcelJS workbook builder), and `insurance-core` (DB interactions and validation). This improves testability and readability.
    - File: [apps/backend/src/modules/insurance/insurance.service.ts](apps/backend/src/modules/insurance/insurance.service.ts)

- Missing tests and CI hooks:
  - There are no unit or integration tests surfaced in `package.json` scripts. Adding tests for `auth.session`, DB repos, and report generation will reduce regressions.

Security and correctness concerns
--------------------------------
- CSRF / refresh token lifecycle:
  - Implementation uses CSRF paired with refresh tokens which is good, but server-side session storage is ephemeral. Use persistent store and rotate tokens carefully.
    - File: [apps/backend/src/core/auth/auth.session.ts](apps/backend/src/core/auth/auth.session.ts)

- Input validation:
  - Most controllers parse raw JSON via `parseBody` and perform ad-hoc validation. Adopt a validation library (e.g., `zod`, `joi`, or `class-validator`) and centralize request schema definitions.
    - File: [apps/backend/src/utils/parseBody.ts](apps/backend/src/utils/parseBody.ts)

- Error handling & logging consistency:
  - Some services throw generic `Error` objects. Define and use typed error classes (e.g., `NotFoundError`, `ValidationError`, `ConflictError`) and map them to HTTP status codes in a centralized error handler.
    - See logger: [apps/backend/src/core/logger/logger.ts](apps/backend/src/core/logger/logger.ts)

Performance & Operational recommendations
---------------------------------------
- Puppeteer scaling:
  - Puppeteer jobs are queued (`POLICY_PDF_MAX_CONCURRENCY`) which is good. Consider:
    - Running Puppeteer inside a short-lived worker/container (e.g., a job queue like BullMQ + worker pool) to isolate memory spikes.
    - Using `puppeteer-core` with Chromium provided by the environment to avoid repeated downloads.

- Database connection and long transactions:
  - Some functions use transactions with `FOR UPDATE` locks across potentially many rows (e.g., cheque attachment). Ensure those transactions are short and indexed to avoid lock contention under load.
    - File: [apps/backend/src/modules/insurance/insurance.service.ts](apps/backend/src/modules/insurance/insurance.service.ts)

Code quality and maintenance suggestions
--------------------------------------
- Break large files into focused modules:
  - Split `insurance.service.ts` into smaller files as noted above. Move helper functions (date/escape/letterhead) into a `report-renderer` utility module.

- Centralize environment validation:
  - Add a startup check that validates required env vars (DB credentials, JWT secrets, Puppeteer flags). Fail fast with clear errors.
    - File: [apps/backend/src/server.ts](apps/backend/src/server.ts)

- Dependency hygiene:
  - Remove workspace-level dev/runtime deps that are only used by one package. Keep `node_modules` size small for frontend contributors.

- Add TypeScript strictness & linting rules:
  - Enforce `strict` TypeScript compiler options in `tsconfig.json` for backend and frontend where feasible; add `eslintrc` rules for consistency.

- Add tests and CI:
  - Implement unit tests for critical logic (auth.session rotation, createRemittanceService, generateMonthlyExcelReport, generatePolicyPdfReport) and add them to CI.

Quick wins (low-effort, high-impact)
----------------------------------
- Move root dependencies to package-level where used: `puppeteer`, `winston`, `axios`.
- Replace in-process `refreshSessions` with Redis-backed store (or at minimum document the limitation clearly in README).
- Add `env` validation at startup (stop app if required secrets missing).
- Split `insurance.service.ts` into at least `reportRenderer.ts`, `pdfGenerator.ts`, `excelExporter.ts`, `insuranceCore.ts`.

Medium-term improvements
-----------------------
- Containerize Puppeteer and run PDF generation in a dedicated worker pool.
- Implement request schema validation with `zod` or `joi` and migrate controllers.
- Add integration tests for auth flows with a mock external auth server.

Long-term / optional
--------------------
- Adopt a job queue for heavy async tasks (PDF, exports) and persist job metadata.
- Add RBAC claims enforcement framework (central permissions store) instead of ad-hoc permission arrays.

--------------------------------------

- Implement a Redis-backed session adapter and replace in-memory Map in `auth.session.ts`.
- Create a small `report` utility module and move HTML-generation helpers out of `insurance.service.ts`.
